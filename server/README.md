# ScanRig Server

Separate Express/MongoDB backend for authentication, personal workout history and the private AI training dataset.

## Setup

```bash
npm install
cp .env.example .env
npm run dev
```

Configure MongoDB and JWT values in `.env`.

## Demo administrator

The server creates/maintains one administrator account from environment variables:

```text
Email:    admin@gmail.com
Password: ADMIN1234
```

These values come from `ADMIN_EMAIL` and `ADMIN_PASSWORD`. **Change them before public deployment.** The password is hashed with bcrypt in MongoDB; it is not embedded in the React frontend.

The administrator is redirected to `/ai-lab`. Normal accounts cannot open the AI Lab, and all `/api/ai-samples/*` routes enforce `role=admin` on the server.

## Main API groups

```text
/api/auth
/api/workouts
/api/ai-samples
```

AI dataset routes support:

```text
GET    /api/ai-samples/summary
GET    /api/ai-samples
POST   /api/ai-samples
PATCH  /api/ai-samples/:id
DELETE /api/ai-samples/:id
GET    /api/ai-samples/export
```

Real AI samples contain normalized pose landmarks, labels and metadata. Webcam video/images are not stored by these routes.

## Admin-triggered retraining

Keep `scanrig-server` and `scanrig-ai` as sibling folders and install the Python AI requirements once:

```bash
cd ../scanrig-ai
pip install -r requirements.txt
```

Then the administrator can click **Retrain ScanRig AI** in `/ai-lab`. The server runs the Python pipeline asynchronously and exposes progress/logs to the Admin UI. Generated ONNX browser-model files are served from:

```text
http://localhost:5000/ai-model/
```

The frontend loads the newest model from that URL after a refresh.

## Stage 19: dynamic exercises and personalization

### Exercise registry

Admin-only endpoints manage custom exercise definitions:

```text
GET    /api/exercises/admin
POST   /api/exercises/admin
PATCH  /api/exercises/admin/:id
DELETE /api/exercises/admin/:id
```

Normal clients only receive Published custom exercises:

```text
GET /api/exercises/public
```

Custom exercises use Draft → Beta → Published. Publishing requires approved real training samples and a successful AI training run that included the class.

### Personalized weekly plan

Authenticated users receive a plan from:

```text
GET /api/personalization/plan
```

The numeric plan is generated by ScanRig's deterministic personalization service. It respects the user's selected training days and uses goal, experience level, desired session length, age band and recent workout/form history to choose volume. Published custom exercises can enter this plan.

### Optional Gemini coach explanation

Gemini is optional. Keep the API key on the server only:

```env
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.7-flash
```

When configured, Gemini writes a short natural-language explanation for the plan. It is explicitly instructed not to change the plan's exercises, days, sets, reps or duration. Without a key, ScanRig returns a deterministic local coaching note.


## Stage 20 ONNX runtime

The retraining job now calls `export_onnx.py`. The AI package validates the exported model with Python ONNX Runtime before the job is marked ready. The server then exposes `web_model/model.onnx` at `/ai-model/model.onnx`.
